# Operations

The generated per-instance skill routes normal chat requests and progressively loads one pinned workflow. Scheduled tasks explicitly invoke that skill and its exact provider binding. Each instance has one authoritative writable backend: Drive or GitHub. Operations never mirror, automatically fail over, or merge generations across providers.

Daily order is recovery/intake, calendar, mandatory per-primary-topic monitoring, bounded discovery, metered queue research, synthesis, verified report save, and native result. Each topic pass has finite query/source counters outside queue attempts. Queue slots 1–5 accept eligible work in numeric order; slots 6–10 are priority-0 only. Resume never resets the local-date budget.

Before initialization, daily, or weekly research, validate the configured provider, immutable container identity, logical root, and canonical generation locator. Drive strict instances require their observed provider/host guard. Drive `best-effort-personal` instances acquire the mapped permanent lock, refuse it while younger than 20 hours, re-check ownership before every external call/write, and set it to unlocked during final cleanup. A stale recovery and the mode's non-atomic residual risk appear in operational reporting.

A qualified GitHub instance always uses `git-fast-forward`: pin the full canonical ref SHA and read all required exact blobs from that commit. If absent, publish and verify the uniquely named immutable operation intent in a small non-force commit, then re-read the head. Validate that durable intent and publish all related canonical path changes/checkpoint with one non-force ref update to a one-parent child commit. Independently verify the ref, parentage, tree, and changed blobs. `409`/`422`, an unexpected head, branch rules, revoked access, public/archive state, truncated inventory, or foreign instance content fails closed. Reconcile from the durable original intent and fresh head; never force-push, rewind, delete the ref, or treat orphaned object creation as completion.

GitHub reads reuse immutable commit/tree/blob identities only within a run, fetch bounded relevant paths through the wiki index, and fall back from a provider-reported truncated recursive tree to complete bounded subtree traversal. Writes batch related paths into one publication. Record calls, bytes, phase latency, rate-limit observations, conflicts, retries, and repository growth without logging private content. Enforce configured per-file/per-transaction limits and report approaching storage limits during weekly work; Git history is retained even after a path is deleted.

Weekly work performs full structural lint and a bounded rotating semantic audit, persists proposals safely, and queues deeper research. It may announce release metadata but cannot upgrade.

V2 reads `TOPICS.md` for user anchors and classified topics; configuration contains only monitored anchor IDs. Shared admission limits active automatic obligations and preserves visible deferred/user work. Peripheral questions cannot spawn research or recurrence, expire at a fixed future maintenance checkpoint, and become compact capsules with source/claim/lineage references. Ordinary retrieval fetches bounded active matches and selective archive entries.

Monitoring reservations, actual query results and inspected sources are separate. Failed coverage does not advance the successful watermark or claim a quiet day. Research failures get persisted future backoff; saved results awaiting merge cannot spend another investigation slot. Risk/rotation maintenance and an overdue-validation selection opportunity share the five normal slots with urgent precedence. Report coverage requires represented summaries or explicit appendix entries and retains deferred IDs for later reports. Publication retries use the saved deterministic payload; notification receipt remains unknown unless observed.

Material monitoring uses a bound raw assessment and source ID/hash/locator checks, just like queued research. Wiki completion receipts must resolve to the matching result/page's original immutable write intent. Unverified claims and pending merges remain visibly partial; a current Drive file ID or GitHub commit/path by itself is not proof. Report finding text carries computed claim status and limitations rather than the research callback's free-form confidence. Unstructured implications remain proposals until their applicability is established. Per-record coverage receipts connect represented evidence to saved reports across local dates without reading historical Markdown on every run.

Receipts are literal states: `SAVED`, `QUEUED`, `ACCEPTED_PENDING_MERGE`, `BLOCKED`, `PARTIAL`. A pending intake is surfaced in queries as user-provided/unmerged. Saved report, published task result, observed notification, and human read are separate states.
