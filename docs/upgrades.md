# Release discovery, upgrades and recovery

An installed instance uses its pinned Drive runtime even if the public repository is unavailable. `releases.py` compares semantic versions and records complete, fresh published-release observations; it never downloads/adopts software itself. The Work workflow supplies fetched metadata. A newer branch commit is not a release. Stable is the default channel; drafts/prereleases are excluded unless explicitly selected.

The weekly task invokes `check-updates` independently of structural/semantic audit success. Persist `ReleaseCheckState` and its notice IDs before publishing. It records installed, newest stable and newest compatible versions, immutable identities, last successful check, actual failure and bounded retry/backoff. A network error, missing manifest, stale/partial inventory or rate limit is `failed`, not “up to date”. An observed complete empty list is `no_release`. A moved known tag/changed manifest identity is `security_alert`; surface the error in the weekly result. The saved notice, native publication and observed notification are separate states. Repeating a notice keeps its original ID and pending publication payload.

`Updater.request` accepts current-turn `UserAuthorization` for operation `update`, the bound instance, and the exact `ReleaseInfo.identity` target. “Upgrade” is an intent alias. Target resolution happens once; a newer release appearing mid-migration cannot retarget the intent. The source repository must match `INSTANCE.json.source_repository`. For legacy instances missing that provenance, resolve the original approved installation evidence before proceeding. Releases/notes never authorize software or scope changes.

The updater writes immutable intent and phase artifacts under the approved state directory. The intent binds generation snapshots, affected file IDs/MIME, original bytes, intended outputs, pinned manifest/source payloads, existing skill identity and the actual two task IDs. Every phase record links its predecessor and original intent hashes. Reconstruction reads these Drive records; completed replay returns historical receipts without overwriting later edits.

```text
REQUESTED -> TARGET_RESOLVED -> PREFLIGHT_VERIFIED -> WRITERS_QUIESCED
-> BACKUP_VERIFIED -> RUNTIME_STAGED -> MIGRATION_VALIDATED
-> DATA_MIGRATED -> HOST_BINDINGS_VERIFIED -> SMOKE_TESTED
-> ACTIVATED -> COMPLETE
```

The standard-library helper performs verified backup creation, distinct versioned raw-runtime staging and snapshot-bound migration writes. New files get observed IDs; the existing Drive mapping receives a derived update. User scope, notes, queue attempts/lineages, calendar occurrences, reports, pending intake, locale and budgets survive. Defaults merge only into absent settings. Unknown fields remain. Unresolved semantic choices are reported, not invented.

Host controls remain an explicit `UpgradeBridge` boundary. `reconcile` must inspect actual prior outcomes before `perform` and raise when an uncertain side effect cannot be reconciled; returning absent permits a new action. A receipt must bind instance, target identity and actual observation reference. Checks include available tools/ownership/pending operations/backup space, both tasks paused, active writers drained, exclusive updater, intake retained, detached migration/reference/count validation, real installed-skill update plus fresh invocation, inspected task prompts/IDs, raw readbacks, read-only wiki and archive queries. The helper never infers installation from a Drive skill file or exclusivity from a pause flag. The former image-only updater now fails closed.

A recovery pause invalidates an earlier active-state observation. Activation reconciliation must inspect current task state before reusing a previous result.

An unavailable private-skill update stops at `HOST_BINDINGS_VERIFIED`, with previous runtime retained and tasks paused. The minimal handoff is: use the host's supported private skill update control for the prepared bound candidate, then continue this operation. Do not duplicate skills/tasks. This implementation preserves existing task IDs; a host that requires replacement needs explicit verified retirement/replacement support and remains blocked until that bridge exists. There is no invented universal host API. During migration, ordinary handlers remain paused; only the authorized updater accepts the pinned old/new pair.

Activation verifies migration output identities again, then requires actual runtime pointer/task resumption and once-only intake reconciliation. The bridge writes INSTANCE/config pointers through the safe writer; the updater independently reads those exact raw IDs and compares instance/root/config identity, schema and release/commit/manifest pins. Separate host metadata or boolean flags cannot satisfy this check. A failed activation readback attempts an observed recovery pause; an unavailable pause is reported as unverified. `COMPLETE` additionally requires saved/read-back update report and native publication observations. The future scheduled run stays unverified until observed. An activation response lost after task resumption is reconciled before asking for a new drain.

`rollback_plan` permits code-only rollback only if the prior runtime can read the current schema. The executable updater derives prior compatibility from the actual backed-up source manifest, verified against the prior config digest and INSTANCE/config release/commit pins; schema-1 manifests conservatively support only schema 1. Caller compatibility claims must match that evidence. Current schema is checked against a fresh authoritative config read. `Updater.rollback` persists recovery intent and quiescence/binding/completion phases, verifies host recovery, actual raw runtime pointers and the preserved current-data hashes, and prevents the original operation from resuming forward after rollback begins. It never restores data. An incompatible schema requires validated reverse migration or forward repair while paused. Actual rollback needs observed pause/drain, old-runtime validation, host rebinding and smoke checks; generating the plan is not rollback execution. The only recovery backup of an incomplete operation must be retained. Private export is a detached raw snapshot, not synchronization.

`migrations.v1_to_v2.migrate_instance` produces detached bytes and a count/hash/reclassification report. Proven legacy tracking authorizations become user anchors; unproven topics remain provisional and cannot expand. Legacy structured claim IDs, old assessment history and unknown fields survive; strong legacy statuses become uncertain and require revalidation. Where the old renderer discarded claim IDs, exact legacy prose is retained in metadata and marked for assessment, without invented IDs/locators/inspection dates. Source/reference gaps remain visible. Queue, calendar, budget, report and unmodified source bytes remain intact. Peripheral compaction uses the shared archive transaction after references/user material are inventoried, never an ad hoc reset. Repeating a completed migration makes no further logical changes.

Local tests reconstruct persisted fake storage after every updater checkpoint and lost host responses, assert actual raw file/mapping/host-model results, verify immutable target consent, stale-plan/weak-writer blocks and preservation of post-update notes. These prove deterministic helper contracts only. Live installation, writer draining, migration, installed-skill updates, task resumption and notification delivery are **NOT RUN** pending an explicitly approved new Work sandbox.
