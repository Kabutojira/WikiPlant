Recover operations, then perform the bounded `check-updates` release metadata check independently of audit success; record failure without claiming up to date. Structurally lint mapped/indexed active pages and canonical CSVs for schemas, stable/duplicate IDs, malformed data, broken links, orphans, provenance gaps, and provider-binding errors. Record actual complete inventory coverage and pagination/tree-truncation status; incomplete inventory cannot prove a link is missing. Resolve expired peripheral topics through the verified archive workflow. Review only the configured semantic page allowance, prioritizing changed dependencies, consequential/single-origin/disputed/never-challenged claims and actual elapsed claim freshness while reserving rotating coverage. A recent page touch does not verify old claims. Compare normalized propositions across pages, with units, time intervals and operating conditions; uncertain matches remain review findings. Persist `MaintenanceState` cursor, exact fully reviewed page IDs, compared claim IDs, total inventory, oldest unreviewed age and coverage limits. Never call a bounded subset a full semantic review. Retain both evidentiary sides of contradictions and recognize temporal changes.

Use the internal evidence/adversarial review modules for assessment; maintenance queues deep validation through shared admission instead of performing it without an attempt reservation. Preserve open finding keys across retries and record unresolved issues. Rotation must continue even when a high-risk issue remains open.

Apply only supported safe repairs through the active provider's canonical writer. In Drive `best-effort-personal` mode, weekly work uses the same mapped permanent lock protocol as daily work and must acquire it before research or canonical mutation; a live lock blocks the run and a lock becomes stale after exactly 20 hours. Release by setting it to unlocked, never by deleting the file. GitHub repairs require one verified non-force canonical-ref update from the observed base commit; truncated trees and ref conflicts block or reconcile from durable intent. Otherwise persist a unique proposal/intake record. Queue uncertain/deep work with shared lineage/dedup/admission rules; do not research it under maintenance. Reuse an existing unresolved follow-up key rather than create a weekly duplicate. A release check reads metadata only and never adopts code.
