# Create and publish a daily report

Refresh the inventory of completed, not-yet-included record IDs and relevant events before synthesis without launching a second unbounded research loop. Use stable report keys and included IDs rather than timestamp-only cutoffs. Rank report significance independently of queue execution priority.

Include material/urgent developments, each primary-topic coverage result, implications and changed assumptions, new connections, today/upcoming events, completed/pending/urgent overflow, and operational/coverage limitations. Quiet reports are brief and honest. Link only real saved evidence.

Save Markdown to the mapped reports folder and independently read it back before publishing the native task result. Track `saved`, `result_published`, `notification_observed`, and `read` separately. Retry publication without repeating research; leave unobservable push/email receipt unknown.
