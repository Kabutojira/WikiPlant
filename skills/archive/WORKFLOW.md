# Compact archive (internal workflow)

At a distinct weekly checkpoint, resolve expired peripheral topics: promote only with new recorded direct-anchor contribution evidence; integrate supported useful findings into a retained page and archive; or archive negative/unresolved findings without an active page. Do not renew expiry after failure or a new mention. Do not autonomously archive a user anchor or silently retire an explicit user request.

Use `ArchiveCapsule` for a concise 100–200-word target summary, excluding structured metadata. Preserve uncertainty and applicability even when this warrants a different word count. Record original classification, anchors/parents, expansion lineage, stable claim IDs, exact evidence locators, dates, stopping reason, negative findings, limits and reactivation conditions. Capacity exclusion is not evidence of irrelevance, and a summary cannot upgrade confidence or corroborate its own sources.

Before planning, completely inventory inbound claim, source, report, queue, calendar and user-note references. Record actual inventory coverage. Save any required evidence still lacking a durable raw reference. Reportable working records must be represented in a saved report/appendix or explicitly deferred before compaction. Drain in-progress canonical writers; a schedule gap or mutable lock file does not establish exclusion.

`plan_archive` binds each mutation to the complete original provider generation. It preserves user notes byte-for-byte and unknown page fields, replaces the canonical topic object with the capsule, updates one derived archive redirect index, removes the old active index entry, archives registry membership, and retires automatic queue/calendar obligations with recorded IDs/reasons. On Drive, replacement uses the same mapped ID; if moving/renaming is unavailable, the raw file stays there and retrieval uses the redirect. On GitHub, all related paths publish in one verified non-force canonical-ref update from the observed base commit. No native document conversion or duplicate editable capsule is permitted.

`execute_archive` persists the original multi-file intent and each verified checkpoint through the active provider's safe writer. `resume_archive` reloads those exact bases from the bound Drive generation or GitHub commit after interruption. A stale input conflicts safely; replay returns historical completion without restoring older content over later edits. Preserve the only recovery copy until all stages verify. A connector without the required safe-writer capabilities keeps a pending proposal and reports the precise blocker.

Include inventoried disposable research dossiers in `plan_archive(disposable_research_files=...)`. `compact_research_dossier` requires exclusive topic ownership, represented/deferred coverage and retained evidence; it replaces generated findings with a capsule reference while preserving IDs, confidence, uncertainty, applicability, correction/lineage fields and unknown user-owned metadata. Never silently move full dossiers to a permanent second archive.

After the configured recovery window, run `compact_recovery_snapshot` only for completed transactions whose current capsule still preserves notes and required evidence. It replaces disposable full original snapshots with compact input/output hashes, retained references and completion receipts. It refuses incomplete operations and unresolved changes. Referenced source evidence and historical reports remain.

Maintain partitioned, derived lookup metadata. `retrieve_archives` fetches only bounded matching partitions/capsules for a question, deduplication or relevant new evidence; daily operation does not load the archive corpus. Report recorded freshness and archived status. Reads never reactivate. Reactivation requires new direct relevance evidence or an explicit user request, shared admission and capacity, with original lineage retained. Report archive counts/bytes as growing historical storage, not a fixed lifetime bound.
